const saveTasksToStorage = (tasks) => {
  try {
    const serializedData = JSON.stringify(tasks);
    localStorage.setItem('flowhub_tasks', serializedData);
  } catch (error) {
    console.error('Failed to save tasks to storage:', error);
  }
};

----------------------------------------------------------------------

[Coach]: That is a very clean utility function! Wrapping browser storage operations in a try...catch block is a great best practice.

What was your reasoning for using JSON.stringify on the tasks data before passing it to localStorage.setItem?

----------------------------------------------------------------------

[Student]: localStorage in web browsers can only accept and store string data. If you pass a JavaScript array or object directly into localStorage.setItem(), JavaScript implicitly converts it using the default .toString() method, which turns your valuable data into the useless "[object Object]" string.

Using JSON.stringify() serializes complex data structures—like arrays of task objects—into a valid JSON text string that preserves all your keys and values, making it possible to safely store the data and later reconstruct it using JSON.parse().

----------------------------------------------------------------------

[Coach]: That is a spot-on explanation! Understanding that localStorage only handles strings—and avoiding the dreaded [object Object] string coercion trap—is key to managing client-side state properly.

What is the primary benefit of breaking your page structure down into reusable partials like partials/header, partials/navigation, and partials/footer?

----------------------------------------------------------------------

[Student]: The primary benefit of using reusable partials is maintainability through the DRY (Don't Repeat Yourself) principle.
Instead of copying and pasting identical HTML structures for your headers, navigation bars, and footers into every single view file, you centralize them into dedicated component files. When you eventually need to update a navigation link, add a new meta tag, or change the copyright year in your footer, you only have to modify that single partial file rather than manually hunting down and editing every page on your site. This eliminates redundant code, drastically reduces the chance of human error, and keeps the project organized as it scales.

----------------------------------------------------------------------

Looking at your layout rules, why did you choose to combine display: flex, flex-direction: column, and min-height: 100vh on the body element?

----------------------------------------------------------------------

[Student]: min-height: 100vh forces the body element to take up at least 100% of the browser viewport's height. By turning the body into a vertical flex container using display: flex and flex-direction: column, you stack the structural components (header, main content, and footer) from top to bottom.
Without this setup, if a page has very little content—like a short form or a brief notification screen—the footer would naturally float halfway up the page right under the text. This technique ensures that the main content area expands to fill any empty space, gracefully pushing the footer down so it always stays anchored at the bottom of the screen.

----------------------------------------------------------------------

[Coach]: That is a perfect explanation of the classic flexbox sticky footer technique! Ensuring the footer stays pinned to the bottom on short pages while flowing naturally on longer ones creates a polished user experience.
